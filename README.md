# AI Mentor — Attendance & Payroll

Автоматический учёт уроков менторов по камере и расчёт зарплаты. Команда BackDeploy.
Стек: **FastAPI · PostgreSQL · OpenCV · Streamlit**.

```
Камера → worker (OpenCV) → backend (FastAPI) → PostgreSQL ← frontend (Streamlit)
```

| Папка | Что внутри |
|---|---|
| `backend/app/rules.py` | правила зачёта урока и формулы зарплаты (чистый Python, покрыт тестами) |
| `backend/app/main.py` | REST API: роли, расписание, отметки камеры, проверка, зарплата, закрытие периода, журнал |
| `worker/` | `enroll.py` — регистрация лиц; `recognize.py` — распознавание с камеры и отправка отметок |
| `frontend/app.py` | интерфейс трёх ролей: ментор, администратор, руководитель |

## Быстрый старт

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env                 # впишите свои SECRET_KEY и CAMERA_API_KEY
docker compose up -d                 # PostgreSQL :5432, pgAdmin :5050

uvicorn backend.app.main:app --reload            # API + /docs на :8000
python -m backend.app.seed                       # демо-данные (таблица со слайда 7)
streamlit run frontend/app.py                    # интерфейс на :8501
```

Демо-логины (после seed; **смените пароли**): `admin/admin12345`, `manager/manager12345`, `mentor1/mentor1-pass`.

### Камера
```bash
# 1. В интерфейсе (Менторы) отметьте согласие ментора — без него регистрация и отметки запрещены.
python -m worker.enroll --mentor-id 1                 # снимет ~30 кадров, обучит модель
python -m worker.recognize --room "Класс 1" --source 0 --show
python -m worker.enroll --forget 1                    # отзыв согласия: удалить фото и переобучить
```
Название кабинета в `--room` должно совпадать с расписанием.

## Как считается урок

1. Камера видит зарегистрированного ментора и шлёт отметки (раз в 30 сек).
2. После конца урока `POST /attendance/evaluate-finished` (воркер вызывает сам раз в 5 мин, или кнопка у администратора) создаёт **одну запись на урок**.
3. Правило: замечен в начале (≤ 10 мин от старта), замечен в конце (≥ конец − 10 мин), присутствие ≥ 80% длительности. Отметки с уверенностью < 0.6 игнорируются. Пороги — в `.env`.
4. Если много сомнительных отметок (низкая уверенность / нет «живого» лица) → статус «проверить».
5. **В зарплату идут только уроки, подтверждённые администратором.** Ставка фиксируется в момент подтверждения.
6. Зарплата = уроки × ставка за урок **или** часы × ставка за час (модель задаётся ментору, не смешиваются).
7. Руководитель закрывает период после выплаты — правки за этот месяц блокируются. Закрыть нельзя, пока есть непроверенные отметки.

Все действия администратора и руководителя пишутся в журнал (`/audit`).

## Роли
- **mentor** — только свои уроки и начисления.
- **admin** — проверка отметок, ручные записи, расписание, менторы, журнал.
- **manager** — менторы, расписание, отчёт и CSV, закрытие периода, журнал.
- **камера** — отдельный ключ `X-API-Key`, видит только список согласившихся менторов.

## Ограничения MVP (честно)
- **Качество распознавания не проверено на реальных лицах.** Используется классический LBPH (быстрый, но чувствителен к свету и ракурсу). Порог `MAX_DISTANCE`/`MIN_CONFIDENCE` нужно калибровать на вашей камере; для продакшена стоит рассмотреть современную модель эмбеддингов.
- **Проверка «живого» лица — грубая эвристика** (движение между кадрами). Видео с телефона она не поймает; защита — ручная проверка спорных отметок и привязка к расписанию.
- Время хранится как локальное время академии (без часовых поясов).
- Таблицы создаются через `create_all`; для продакшена добавьте миграции (Alembic), HTTPS и смену всех секретов.
- Лица — биометрия: храните `data/faces` с ограниченным доступом, задайте срок хранения.
